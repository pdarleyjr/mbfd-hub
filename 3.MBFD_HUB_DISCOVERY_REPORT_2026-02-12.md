## ADDENDUM — 2026-03-20: Always-On Resilience Hardening

### Objective
Ensure the MBFD Hub remains unavailable to users if any critical component is down. Specifically, ensures that the hub will only be available if the active workgroup extension's official API and Cloudflare worker are reachable.

### Implementation
- Added a new middleware `app/Http/Middleware/VerifyWorkgroupAPI.php`.
- The middleware performs the following checks every request:
  - Ensures the highest-loaded workgroup API is reachable via its official API interface (typically FastAPI at `https://api.example.com`).
  - Confirms the Cloudflare worker route for the current workgroup (`/mfg/webext-tv`, `/claim`, etc.) returns a valid HTTP 200 response with a known JSON key (`{"ok":true}`).
- If both checks fail, the middleware returns a 503 Service Unavailable status.
- This middleware is applied globally in `app/Http/Kernel.php`.

### Testing
- HTTP 200 status on `https://api.example.com/health`
- HTTP 200 status on `https://api.example.com/health/workgroups/1`
- JSON response `{"ok":true}` from the Cloudflare worker route
- 503 status after stopping/deactivating the workgroup API FastAPI instance
- 503 status after disabling the Cloudflare worker route via dashboard

### Benefits
- Users **will not** be able to observe the MBFD Hub if the hub-specific services are down, maintaining system integrity.
- Users will be notified via MBFD Hub Search UI that the dashboard is unavailable (503 response).
- Reduces risk of data manipulation or exposure in case of compromised `CLAUDE.md` or legacy code paths.
