### ERROR-037: Dual Service Worker Registration Causes Infinite Page Reload Loop
**Date**: 2026-03-21  
**Severity**: CRITICAL  
**Introduced by**: DeerFlow 2.0 agent commit `c876f7ff` (PM Cycle integration)  
**Fix commit**: `7cfcdd9f`

**What happened**: The `main.tsx` entry point registered `/daily/sw.js?v=2026-03-09-vehicle-inspections-fix-2` while `registerSW.js` (auto-injected by vite-plugin-pwa) separately registered `/daily/sw.js` (no query string). The browser treated these as different SW URLs. On every page load:
1. Both registrations competed, triggering constant `updatefound` events
2. `controllerchange` listener called `window.location.reload()`
3. The guard variable `hasReloadedForNewServiceWorker` reset on each reload (module-level var)
4. Result: infinite reload loop — page never renders, spinner forever

**Impact**: The entire Vehicle Inspection SPA (`/daily/vehicle-inspections/*`) was completely unusable. Selecting any apparatus triggered an infinite reload that also hammered the API with 429 rate-limit responses.

**Fix applied**:
1. Removed the duplicate SW registration block from `main.tsx` — vite-plugin-pwa's `registerSW.js` is the sole registrar
2. Removed stale `public/daily/service-worker.js` (superseded by Workbox `sw.js`)
3. Rebuilt React assets so new `sw.js` precache manifest references correct file hashes

**Prevention rule**:
- **NEVER register a service worker in application code** when using vite-plugin-pwa — it handles registration automatically via `registerSW.js`
- **NEVER add `?v=` cache-busting query strings** to SW registration URLs — this creates a "different" SW in the browser's eyes
- If SW update behavior is needed, configure it in `vite.config.ts` PWA plugin options, not in `main.tsx`

### ERROR-071: Filament Base Theme CSS Import Removed — Total UI Destruction
**Date**: 2026-03-20  
**Severity**: CRITICAL  
**Commit that broke it**: `ae9e5858` ("fix: remove broken Filament vendor import from theme.css")  
**Fix commit**: `a17d3185` ("fix: restore Filament base theme CSS import (ERROR-071)")

**What happened**: A previous agent removed the `@import '../../../../vendor/filament/filament/dist/theme.css';` line from `resources/css/filament/admin/theme.css`, claiming the file did not exist (ENOENT). The file **does exist** (106KB) in the vendor directory and contains ALL of Filament's base Tailwind/CSS styles.

**Impact**: The entire web application rendered completely unstyled — giant SVG icons, no layout, no Tailwind utilities, broken across ALL pages and ALL panels (Admin, Workgroup, Training).

**Root cause**: The agent likely ran `npm run build` from a context where `vendor/` was not mounted or accessible (e.g., outside the Docker container), got an ENOENT error, and "fixed" it by removing the import instead of fixing the build environment.

**Fix**: Restored the `@import` line at the top of `resources/css/filament/admin/theme.css`, ran `npm run build`, and cleared all Laravel caches.

**Prevention rule**: 
- **NEVER remove `@import` lines from Filament theme CSS files** without verifying the referenced file exists inside the Docker container where the app runs.
- The `vendor/filament/filament/dist/theme.css` file is installed by Composer and is REQUIRED for Filament v3 custom themes.
- If `npm run build` fails with ENOENT for vendor files, the fix is to ensure `vendor/` is properly installed (`composer install`), NOT to remove the import.

### ERROR-081: ApparatusResource Table Header/Body Column Misalignment — Brittle CSS Patches
**Date**: 2026-03-21  
**Severity**: HIGH  
**Fixed by**: Kilo Code (code mode) alignment enum remediation

**What happened**: The `ApparatusResource` table columns lacked explicit `->alignment()` declarations using the `Filament\Support\Enums\Alignment` enum. Columns like `designation`, `vehicle_number`, and `location_display` relied on framework defaults. Adjacent columns used `->width('1%')` — a brittle CSS hack that broke header-to-body parity when the browser calculated flex-basis for the `<th>` and `<td>` pairs. This resulted in a visible "zig-zag" drift between headers and data cells, reducing legibility in the fleet management table.

**Root cause summary**:
1. No `use Filament\Support\Enums\Alignment` import in the resource file
2. `->width('1%')` used on `designation`, `vehicle_number`, `status`, and `pm_health_status` columns — bypasses Filament's coordinated header-to-cell layout synchronization
3. `location_display` computed column had no alignment anchor — dynamic string concatenation caused flex-basis drift

**Fix applied** (`app/Filament/Resources/ApparatusResource.php`):
1. Added `use Filament\Support\Enums\Alignment;` import
2. Removed all `->width()` calls from default visible columns
3. Applied `->alignment(Alignment::Center)` to: `designation`, `vehicle_number`, `status`, `pm_health_status`, `inspections_count`, `active_defects_count`, `class_description`, `station.station_number`, `unit_id`, `year`, `last_service_date`, `reported_at`, `created_at`
4. Applied `->alignment(Alignment::Start)` to: `location_display`, `notes`, `assignment`, `current_location`, `make`, `model`, `vin`
5. Applied `->alignment(Alignment::End)` to: `current_engine_hours`, `current_miles`, `mileage`

**Prevention rules**:
- **ALWAYS import and use `Filament\Support\Enums\Alignment`** for column alignment in Filament v3 — string-based attributes are not recognized
- **NEVER use `->width()` as an alignment substitute** — it breaks the framework's coordinated `<th>`/`<td>` layout sync
- **Computed columns using `getStateUsing()` or `->state()` MUST declare `->alignment()`** — the framework cannot predict dynamic string widths
- The `->striped()` method on the `$table` object provides visual lane separation and should ALWAYS be present in complex resource tables to assist alignment verification
