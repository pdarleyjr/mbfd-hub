# MBFD Hub — Impeccable Design System

> Generated 2026-04-13 | Updated by Claude Code sessions

---

## Design Context

### Users
Dual audience: **firefighters and station personnel** checking in at station kiosks or mobile browsers (high-urgency operational context), and the **general public** visiting mbfdhub.com for community transparency. Admin staff and officers use the Filament panel via desktop. The live call feed serves both audiences simultaneously — personnel need fast, scannable CAD-style data; the public needs clear, professional incident information without alarmism.

### Brand Personality
**Authoritative. Trusted. Responsive.**

Miami Beach Fire Department is an emergency services agency. The interface must project the same qualities as the department itself: disciplined, professional, reliable. It is not playful or expressive — it is clear, fast, and dependable. Emergency red as a controlled accent (not alarm), dark navy authority, warm neutrals that feel human rather than clinical.

### Aesthetic Direction
- **Visual tone**: Professional CAD-display meets modern civic tech. Think: operational readiness dashboard.
- **Theme**: Light mode primary (public-facing). Dark header/nav for authority.
- **References**: Government data dashboards, professional emergency dispatch UIs, Vercel/Linear for spacing/typography polish.
- **Anti-references**: Consumer apps (playful shadows, bouncy animations, emoji-heavy), cold gray corporate SaaS.
- **Emotional goal**: Confidence and calm urgency. Users should feel informed and trusting, never anxious or overwhelmed.

### Design Principles

1. **Function before form** — Every visual element must justify its presence with utility. No decoration for its own sake. Incident data must be scannable in under 2 seconds.

2. **Warm professionalism** — Replace all cold grays with warm stone/neutral tones. Red is reserved for primary CTAs and active incident accents only — not decorative.

3. **Tabular discipline** — All numeric data (incident times, unit counts, IDs) uses `font-variant-numeric: tabular-nums` to prevent layout shift. Times and counts never jump.

4. **Motion with restraint** — Staggered reveals for new call entries, shimmer skeletons while loading. All transitions use professional easing (ease-out, no bounce). Always respect `prefers-reduced-motion`.

5. **Mobile-first safety** — The landing page is viewed on station iPads and firefighter phones. Safe-area insets, minimum 44px touch targets, no hover-only interactions. Pointer-aware sizing via `@media (hover: none)`.

## Motion Rules

```css
/* Professional easing only — no bounce */
transition-timing-function: cubic-bezier(0.4, 0, 0.2, 1); /* ease-in-out */
transition-timing-function: cubic-bezier(0, 0, 0.2, 1);   /* ease-out (preferred) */

/* Duration limits */
--duration-fast:   150ms;  /* Micro-interactions */
--duration-base:   200ms;  /* Hover states */
--duration-slow:   300ms;  /* Content transitions */
--duration-reveal: 400ms;  /* Staggered list reveals */

/* Always gate motion */
@media (prefers-reduced-motion: reduce) {
  /* Remove all transitions, use opacity 1 directly */
}
```

## Critical Rules (Violations = Production Bugs)

| Rule | Error Code | Why |
|---|---|---|
| NO `@apply` in CSS | ERROR-031 | Causes iOS Safari crashes |
| NO Tailwind CDN | ERROR-032 | Production performance violation |
| NO cold gray (`gray-*`, `slate-50`) | ERROR-033 | Brand violation, use warm `stone-*` |
| NO bouncy easing | ERROR-034 | Unprofessional motion |
| ALWAYS `tabular-nums` on numeric data | ERROR-035 | Layout shift on timer updates |
| ALWAYS `prefers-reduced-motion` gate | ERROR-036 | Accessibility |
| ALWAYS 44px min touch targets | ERROR-037 | Mobile usability |
| ALWAYS safe-area insets on mobile | ERROR-038 | iPhone notch/home bar overlap |

## Live Call Feed Specific Rules

- **Polling**: Server-side via Laravel Reverb WebSocket — client never calls PulsePoint directly
- **Stale indicator**: Show "Last updated X min ago" badge if WebSocket drops
- **Max visible calls**: 8 on desktop, 5 on mobile (with scroll-snap for overflow)
- **Empty state**: "No active incidents" with shield icon — never blank
- **Error state**: "Monitoring unavailable" — never show raw error messages
- **Timestamps**: Always display as HH:MM (no seconds) in 24h format using tabular-nums
- **Unit numbers**: Monospace font (JetBrains Mono) to prevent width shift

## Stack & Implementation Constraints (emit code for THIS stack, not the generic default)

> Added 2026-06-02 so design/UI skills generate framework-correct code instead of Next.js/Tailwind-v4 defaults.

- **Frontend = React 19 SPAs via Vite 6**, mounted into Blade. There are several independent mini-SPAs (apparatus-layout, daily-checkout PWA, pump-simulator, workgroup-dashboard), each with its own entry + Vite config.
- **NEVER emit**: Next.js, React Server Components, `"use client"`, `next/font`, `next/image`, the app-router, or Tailwind v4 `@theme` CSS-first config. None exist here.
- **Tailwind = v3** (`tailwind.config.js` with `theme.extend`, PostCSS 8 + autoprefixer). Brand tokens already defined: `colors.mbfd.{red #B91C1C, light #DC2626, dark #991B1B}`, warm `neutral.50-900`, `fontFamily` sans=Source Sans 3 / heading=Plus Jakarta Sans / mono=JetBrains Mono, and a fluid `clamp()` `fontSize` scale. Reuse these; do not invent a palette.
- **Motion = framer-motion 12** (already a dependency). Use it (gate with `useReducedMotion`); do not hand-roll keyframes where FM fits, and do not add GSAP (not a dependency).
- **State** = TanStack Query 5 (server) + Zustand 5 (UI). **Canvas** = Konva 10 / react-konva (apparatus editor). **Icons** = lucide-react. **Offline** = dexie + vite-plugin-pwa.
- **Admin = Laravel 11 + Filament 3** (Blade/PHP, panel at `/admin`). Admin UI is Blade + Filament components + Tailwind, NOT React. Do not propose React widgets where Filament panels live.
- Hard rules above (no `@apply`, warm stone only, tabular-nums, reduced-motion, 44px, safe-area) are production constraints (ERROR-031..038), not preferences.
