## Mandatory Recovery Sequence (After ANY DeerFlow Restart)

```bash
cd ~/src/deer-flow/docker && docker compose -f docker-compose-dev.yaml restart
docker exec deer-flow-langgraph chmod -R 777 /app/backend/.deer-flow/
docker exec deer-flow-gateway chmod -R 777 /app/backend/.deer-flow/
docker exec deer-flow-langgraph uv pip install duckduckgo-search --python /app/backend/.venv/bin/python
for s in $(docker ps --filter name=deer-flow-sandbox --format '{{.Names}}'); do
  docker exec $s chmod -R 777 /mnt/user-data/
done
docker exec deer-flow-nginx nginx -s reload
docker exec deer-flow-gateway curl -sf http://langgraph:2024/ok
```

> **Note**: After `wsl --shutdown`, the `deerflow-recovery.service` handles permissions + nginx reload automatically. But `duckduckgo-search` must be reinstalled manually after container restart since it's not baked into the Docker image.

## WSL2 Persistence Architecture

### How It Works
1. **`WSL-KeepAlive` Windows Scheduled Task** (PRIMARY) — runs `wsl -u root -- bash -c "while true; do sleep 300; done"` at logon, preventing Windows from ever suspending the WSL VM. This is the actual fix. `vmIdleTimeout=-1` in `.wslconfig` did NOT work.
2. `C:\Users\Peter Darley\.wslconfig` has `vmIdleTimeout=86400000` (24h), `memory=16GB`, `autoMemoryReclaim=dropcache`
3. `/etc/wsl.conf` has `[boot] systemd=true` — enables native systemd on WSL boot
4. `docker.service` + `containerd.service` are `systemctl enable`d — auto-start with systemd
5. All DeerFlow containers have `restart: unless-stopped` — auto-start when Docker starts
6. `deerflow-recovery.service` runs 15s after Docker — fixes permissions + nginx DNS

### Key Files
| File | Purpose |
|---|---|
| Windows Task: `WSL-KeepAlive` | Keeps WSL VM alive permanently (at logon) |
| `C:\Users\Peter Darley\.wslconfig` | `memory=16GB`, `autoMemoryReclaim=dropcache`, `vmIdleTimeout=86400000` |
| `/etc/wsl.conf` | `systemd=true`, `default=devcontainers` |
| `/etc/docker/daemon.json` | Log rotation: `max-size: 10m`, `max-file: 3` |

## Known Issues (2026-03-19)

### File Uploads via Remote URL / Telegram — Permission Denied
- **Status**: OPEN
- **Symptom**: Uploading files through `code.mbfdhub.com` or `@MBFDHubBot` Telegram bot fails with `Permission denied: '/mnt/user-data/uploads/'`
- **Root cause**: New sandbox containers have `/mnt/user-data` as `root:755`. The permanent fix in `aio_sandbox_provider.py` may not execute correctly after the sysbox flag removal (ERROR-077).
- **Workaround**: `for s in $(docker ps --filter name=deer-flow-sandbox --format '{{.Names}}'); do docker exec $s chmod -R 777 /mnt/user-data/; done`
- **Local uploads work** after applying the workaround
